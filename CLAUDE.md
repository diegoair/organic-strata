## What

**Organica** is two things simultaneously:
1. Studio Rann's visual language system
2. The AI-powered toolset to develop, generate, and deploy that language

The visual language is built on three references tuned together:
- **Biomimicry** — perfect organic geometries (nautilus, phyllotaxis, cellular growth)
- **Raw organic nature** — imperfect, living forms (drop marks, erosion, growth patterns)
- **Street art language** — bold marks, scale, presence, immediacy — the calibration mechanism that makes the other two feel grounded, not academic

The fundamental gesture is the **drop mark**: pigment dropped onto a surface, governed by gravity, viscosity, surface tension. Not drawn — allowed to happen. Two atoms: **drop + brushstroke**. Everything else derives from these.

## The Methodology

Based on **"Flexible Visual Systems"** by Martin Lorenz.  
Core principle: a visual system is a **grammar** — rules that generate infinite variations while remaining coherent.

Modules in Organica:
- **Form** — drop marks, brushstrokes, traced hand-drawn shapes
- **Pattern** — tiling/repetition (manual now, automated in roadmap)
- **Grid** — Genesis composer N×N cells
- **Color** — 3 base palettes (sky & sun / earth / deep sea), expandable
- **Typography** — undefined, TBD
- **Motion** — 55 organic CSS animations (Genesis library)
- **Scale** — vector-first, screen to mural

## Critical Rules — Never Break These

- **Design tokens — mandatory, every new development.** Never hardcode a font-size, spacing (padding/margin/gap), radius, or UI-chrome colour — use the matching token from `shared/organica-tokens.css` (`--fs-*`, `--space-*`, `--radius-*`, `--ink`/`--paper`/`--panel`/`--mid`/`--border`/`--border-strong`/`--tool`/`--accent-warm`/`--track-bg`). If the value you need doesn't exist on any existing scale, **stop and ask before adding a new token** — don't invent one silently and don't fall back to a raw px/hex "just this once." Live reference with every token and component, rendered from the real CSS: `/design-system/` (linked from the hub). Full narrative + Figma mapping: `docs/DESIGN-SYSTEM.md`. Two real exceptions, not loopholes: (1) a tool's own **content** colour (Halide's ink/paper for the dithered image, Pollen's point colour) is user data, not design-system chrome — don't tokenise it just because it happens to default near `--ink`/`--paper`; (2) a genuine pill/stadium shape (`border-radius` = half the element's height, e.g. a toggle switch) isn't a corner radius — forcing it onto `--radius-sm/md/lg` flattens the capsule. Typography specifically: **Manrope only**, via `--font`, never a second typeface.
- **Shared code** — `shared/organica-core.js` owns download, preset storage + legacy migration, Figma postMessage, colour hex validation, the rectilinear contour tracer and zoom/pan. Don't re-implement these in a tool; if one needs different behaviour, extend the core
- **New tool** — start from `shared/_template.html`, not by copying a neighbour. Contract: `docs/UI-SHELL.md`
- **`organic-animations.css`** — never modify existing rules, only append new ones (the 55 forms depend on the exact timings/selectors). This is the split-out pure half of the old `organic-library.css`; the append-only rule now lives here. Any consumer linking it **must** define `--ink` and `--bg-cell` — see `docs/SHARED-LIBRARY.md`
- **`organic-library.css`** — now an `@import` shim (`organic-page.css` + `organic-animations.css`, in that order — the order is load-bearing for the cascade). Don't put rules back into it
- **localStorage keys** — always `organica.<tool>.<thing>`. When renaming a key, migrate forward and **leave the legacy key in place** (user presets/forms are real work); never delete it in the same release
- **`organic-forms.js` / `organic-defs.js`** — treat as data, port verbatim
- **`backend/`** — do not touch Python files unless explicitly asked
- **`strata/`** — do not touch unless explicitly asked
- **Color in SVG forms** — always `fill: var(--ink)` / `stroke: var(--ink)`, never hardcode hex
- **Internal links** — always relative (`/genesis/`, `/strata/`), never absolute Vercel URLs
- **New forms** — follow the pattern in ANIMATION-SYSTEM.md, test in indicators.html first

## Animation System — Quick Reference

6 patterns, each maps to real physics:

1. **Internal Pressure** — `scale` + asymmetric `cubic-bezier` → breath, heartbeat, lung
2. **Gravity + Viscosity** — `translateY` + `scaleY` → drops, honey, lava
3. **Growth by Tracing** — `stroke-dashoffset` → vine, roots, tree rings
4. **Collective Behaviour** — staggered `animation-delay` + goo filter → swarm, metaballs
5. **Environmental Forces** — continuous `translate`, `linear` easing → wind, tide, sedimentation
6. **Differential Rotation** — counter-spinning layers at different speeds → orbit, shard rotation

Duration range `1.4s–14s` maps to real-world time scales. See `docs/ANIMATION-SYSTEM.md` for full detail.

Replicates 木漏れ日 — dappled sunlight through a canopy — via the three real graphics mechanics Diego named: **(1) light cookie / gobo** — a canopy mask (procedural 2-layer fBm foliage combined with `max()` so gaps only exist where both layers open; OR an uploaded silhouette, so a Halide 1-bit export / Strata trace / photo drops straight in as the canopy) projected onto a ground plane in perspective, two layers domain-warped at different rates = wind; **(2) penumbra + pinhole** — the detail nobody implements and the thing that *makes* it komorebi: the sun subtends ~0.53°, so a gap at height h blurs its shadow edge by ≈ h/108, and once a gap is smaller than that blur it becomes a pinhole projecting a round disc of the sun instead of the leaf shape. - **August 3, 2026 (later same day) — Camouflage output-quality audit: four measured defects, all fixed.** Diego's verdict on the three-mode build was that output quality was "limitata e mediocre". Rather than tune by eye, each mode was **measured**, and four distinct root causes came out — all the same underlying mistake in different clothes: **an internal representation leaking into the output**. **(1) Render resolution.** 54% of a settled field's cells hold an *intermediate* value — more than half the field is edge information — and the build threw all of it away by thresholding per CELL, writing an N×N ImageData and letting `drawImage` upscale: on a 128 grid at 640px, each of ~1,717 boundary cells became a hard **5-pixel stair-step**. Now the field is sampled **bilinearly at output-pixel resolution** with the threshold applied there; the simulation grid is untouched, this is purely how it's drawn (9.2ms/frame, 74fps with the solver — an affordable trade for the most visible defect in the tool). **(2) Dazzle facet distribution.** Measured: largest facet **29.6%** of canvas, top three **65.2%**, largest:smallest **1162×**, two thin slivers (perimeter²/area 689 vs 16 for a square) — i.e. "three blobs", not dazzle. Two causes: the cut point was **uniformly random in the bbox** (near an edge half the time = one huge piece + one sliver) and recursion was **depth-driven**, so a facet that won the big half stayed big regardless of size. Now cuts pass near the polygon **centroid** (±18%) and recursion is **area-driven**. After: largest **4.1%**, top three **12.1%**, ratio **3×**, worst sliver **55**, zero over 100. `Fragments` changed meaning from recursion depth (2–8) to approximate **facet count** (4–80) — what its label always implied. **(3) Structural colour.** The build mapped angle onto the **full 0–360° hue wheel** at fixed saturation: the classic rainbow colormap, ignoring the user's own Ink/Paper — and backwards from the phenomenon it cites, since `Research_Report_Camouflage.md` §1 is explicit that a Morpho's blue is a Bragg stack reflecting *"una banda stretta di lunghezze d'onda (~460nm)"*. Now a **76° arc anchored on the user's Ink hue** (falling back to Morpho blue 220° when Ink is achromatic, as the default is). A second defect found alongside: the gradient was sampled over a **sub-cell step**, and bilinear interpolation has a constant derivative inside a cell — so every pixel in a cell got the same hue, producing visible cell-sized facets; the step is now a full cell. **(4) SVG geometry.** The shared `Organica.contoursToPathD` walks CELL edges and emits axis-aligned segments — exactly right for Halide (where the subject *is* dithered square pixels), exactly wrong for organic blobs: measured **26 right-angle vertices per spot**, 1,220 straight segments, **zero curves**. Camouflage now reuses the shared tracer for **topology** (loop/hole detection, which is correct and worth sharing) and replaces only the **geometry** — decimate, low-pass filter, emit Catmull-Rom **cubic Béziers**: 1,209 curves, 0 straight lines, verified by overlaying the exported SVG on the canvas. The shared tracer is deliberately **not** modified (Halide depends on it), and Dazzle correctly still exports straight lines only since its facets are meant to be sharp. **(5) Countershade shading curve** — a physics error rather than a measurement: it ramped **linearly** from a flat plateau, which is why it read as "a flat area with dark edges" instead of a rounded form. Real self-shading has no plateau — a cylinder's Lambertian brightness is **√(1−x²)**, the rounded shoulder that *is* Thayer's countershading. Now 17 sampled stops shared by canvas and SVG so the two can't drift, with Falloff as the power. Verified end to end: all 7 mode×palette combinations export valid SVG, seed reproducibility intact, canvas restore after export correct, 0 unnamed controls, no console errors. Full before/after numbers: `docs/CAMOUFLAGE.md` §11b.

(2) Rotating the *sampling* instead, with **bilinear** taps, fixed the topology at 50° but a direct ratio measurement (mean-squared step along vs across the stripe) explained why it still read soft: **9.24× at θ=0°** (exact grid lookup) collapsed to **2.15× at θ=50°** (bilinear blends in neighbours, leaking diffusion into the axis meant to be suppressed) — Catmull-Rom made it *worse*, confirming the leak scales with interpolation smoothness. (3) **Shipped: nearest-neighbour taps** — no interpolation, no blur to leak, clean directional split verified at every angle tested; the trade (faint lattice-aliasing stipple) is minor at Grid=Fine and part of why the new "True stripes (zebra)" preset sets it. New controls: Anisotropy › Amount (0 = original kernel, unchanged — every existing preset stays on it) and Direction. At high Anisotropy, `seed()` also switches from random blobs to seeds **laid out along the stripe direction and repeated across the perpendicular axis** — the first version kept random placement and produced clean stripes near the few seed points with blank canvas everywhere else, since suppressed perpendicular diffusion can no longer carry information sideways to unseeded regions. **Seed from shape**: a third Seed shape option opens a file picker (Halide/Strata output drops straight in) and seeds B only inside the dark region via the same **masked reaction-diffusion** Living Path already uses on glyphs — cells outside the mask are pinned to the resting state every step, not just at t=0, so the pattern can't leak past the silhouette no matter how long it runs. - **August 3, 2026 (still later same day) — Camouflage: two real bugs + convergence readout.** Asked to re-explain the Disruptive algorithm and all its presets; documenting it against the actual code surfaced two bugs the UI was hiding. **(1) `Sites` was dead whenever Anisotropy > 0.3** — the anisotropic branch of `seed()` lays nucleation points out as rows along the stripe direction and never read the control; measured at Anisotropy 0.85, Sites 5/20/40 all seeded exactly **675 cells**. Sites now drives the row spacing, but over a deliberately narrower range than on the isotropic path, and that is physics rather than a UI compromise: suppressed perpendicular diffusion can't carry the pattern sideways into an unseeded band, so sparse rows leave bare canvas. **My first attempt did exactly that** — mapping Sites straight onto a row count seeded 3 rows on a 176 grid at the default and left most of the frame empty; caught by looking at the render, not at the numbers, and fixed by interpolating between "just dense enough to fill" and "tightly packed" with the default landing on the previously-hardcoded spacing. **(2) The canonical f/k values were literally unreachable** — a range input snaps to `min + n·step`, and at `step="0.0005"` the Pearson/Munafo spots-mitosis pair fell between stops: f 0.0367 → **0.0365**, k 0.0649 → **0.0650**. So the `Leopard spots` preset declared one pair and the simulation ran another (visible in the status bar all along). Step on f/k/f2/k2 is now 0.0001 and both are exact; Coral labyrinth's 0.0545/0.0620 happened to land on a stop and were always right. **(3) The simulation stopped too early** — the symptom Diego actually reported ("l'animazione a un certo punto si ferma"). The stop is deliberate (Gray-Scott converges), but the test was "mean per-cell change per step under 4e-5", and measuring showed three things wrong with it: `lastDiff` **never reaches zero** (it settles on a noise plateau at ~2.4e-5, barely under the cutoff, so the cutoff fired mid-evolution — and lowering it would mean never stopping); it is **not monotonic** (traced `f19 6.2e-5 ↓ · f31 5.1e-5 ↑ · f55 1.6e-4 ↑`, because Gray-Scott has an *expansion* phase where spots multiply and change climbs again); and at the old stop point the structure was still forming (47 blobs / 25.8% ink, versus 49 / 26.7% when left to run — it was stopping mid-mitosis). **Two replacement criteria failed before the third worked**, each caught by measurement: "stopped improving" on `lastDiff` fires during the expansion climb and was *worse* (stopped at 1.2s with **30.7%** of cells still to flip); "drift stopped improving" never fires at all, since drift decays smoothly and indefinitely (Giant cell 35% → 11% → 8% → 4% → 1% of peak, no plateau) so it ran to the 30s cap while ink% had been flat since 7.5s. Shipped: measure the **field** the way a viewer would — snapshot, wait a window, see how far the picture moved — and stop when drift falls to **12% of that run's own peak**, counted cumulatively because drift spikes back up occasionally (7.4% → 15.0% → 8.0%) and a consecutive counter resets on every blip. Also scaled **steps per frame by 1/dt**, since Feature size lowers dt and `Giant cell` was overrunning the cap purely because each frame advanced less simulated time. Result: Leopard spots 6.6s/11.0%-still-to-flip → 8.5s/8.5%; Giant cell 30s-cap → 6.0s/4.0%. **Disclosed honestly**: the residual never reaches zero — once the structure is fixed the features still migrate slowly forever (16.3% → 7.9% → 5.2% flip at 6k/12k/20k steps); the criterion guarantees the *structure* has settled, not every pixel. **(4) Convergence readout** — "Simmering…" now carries a percentage. Two refinements from watching a real run: the signal **rises** during growth, pinning a first-sample baseline at 0% for half the run (fixed by baselining on the peak), and it fluctuates near the end, making the readout go **85% → 81% → 99%** (fixed by making it monotonic).
