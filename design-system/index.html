Every token and component Organica is built from, rendered with the exact CSS every tool loads (shared/tokens.css, header.css, panel.css, floatbar.css, shell.css). Nothing on this page is a copy — change a value in shared/ and this page changes with it, same as every tool.

Foundations

Typography

One family — Wix Madefor Display, variable weight 400–800 — via --font (Manrope until Sep 29, 2026; still the fallback). There is no 300, so --w-light renders as 400. The panel runs on exactly two styles (10/400 and 9/300); everything outside the panel uses the type scale below. No second typeface, no hardcoded font-size.

Role tokens — what components actually reference

A panel component never names a size directly; it names a role, and the role points at a step in the scale above. Change what a section title weighs in one place and every tool follows. This indirection is why the whole panel runs on just two pairs — 10/400 and 9/300. Values below are read live from the stylesheet.

--t-section-size · --t-section-weightSection title — /
--t-sublabel-size · --t-sublabel-weightSub-label — /

--t-control-size · --t-control-weightControl text — /

Line height & letter spacing

Line heights are unitless so they scale with the element's own size. --ls-normal is 0 and is written explicitly rather than omitted — panel.css uses it 11 times, because "no tracking" is a decision the panel makes deliberately against a house voice that is otherwise tracked.

--lh-snug — multi-line labels in panels
--lh-normal — body copy, docs, help text
--ls-normal — panel labels: no tracking, on purpose
--ls-wide — values, hex fields, readouts
--ls-wider — buttons, control labels
--ls-widest — uppercase micro-labels, the tool logo

Retired 2026-09-06: --fs-display, --lh-tight, --ls-tight and the --sans/--mono/--display typeface aliases. --fs-display described a clamp(1.5rem, 9vw, 13rem) hero wordmark that no longer exists — the hub's is a 0.95rem corner logo. The scale comment documenting it outlived the token's only consumer, which is the more useful half of the lesson.

Color tokens

--ink/--paper/--panel/--mid/--border/--accent are the surface palette. They're defaults in tokens.css now — 15 of 17 tools shipped byte-identical values, so a tool declares only --tool (its identity hue) plus the rare real override (--ink #241b14 for the warm-black trio, --mid #726a5e for Blob Boundary). --accent-warm, --track-bg and --danger are fixed, the same in every tool. A tool's own content colour (Halide's ink/paper, Pollen's dots) is still local — that's user data, not a role.

Canvas area & stage

Two surfaces, two rules — the same in every tool (Sep 29, 2026).

Defined inshared/tokens.cssshared/shell.cssUsed inevery tool with a canvas
  1. The canvas area (what the stage sits on — #canvas-wrap / .org-canvas-wrap, or a tool's own stage area) is always background: var(--canvas-grid), var(--canvas-bg); — white with the light cyan dot grid (--canvas-dot, 24px pitch). Never --panel: that grey is for interface chrome (inputs, selected rows, the floating bar).
  2. The stage (the sheet you draw on) gets its look from the class .org-stage, never from its id. Ids differ per tool (#board, #preview, #view-canvas, #gl-canvas…) because each script finds its sheet by id. A tool that can't add the class (a p5 canvas, an SVG rendered by the tool) uses the token directly: box-shadow: var(--stage-shadow);. Never retype the shadow.
  3. The stage's own colour is user content — a tool's Paper (Living Path's cream, a transparent FVS paper) is not tokenised.
  4. Text is always var(--font) — including text drawn on a <canvas>, which can't read CSS variables: resolve it at draw time with getComputedStyle(document.documentElement).getPropertyValue('--font') (see shared/glyph-editor.js). No monospace, no system-ui, no Georgia for interface text.

Exceptions, on purpose: Rhizome is an infinite node canvas (the dot grid, no sheet); Mote's kiosk mode is black; a font the user loads (Living Path / Apostate specimen) is content.

Slider

One slider, everywhere — the Slosh slider (after Bencho's, MIT). A grey --track-bg well with an --ink liquid that has mass: the handle (a round droplet, shared with the switch) is rigid under your finger; the liquid is a softer spring behind it that overshoots, rocks into the end stop and leans on its leading edge. A dotted centre line runs through it, and the number beside it is drag-to-scrub and click-to-type. It replaced the previous Figma-style slider (5px line, round thumb, eased --fill), which is removed.

Tokens. Height --slo-h (= --row-h − --space-2) is shared by the track, the handle and the number box; the corner --slo-r is --radius-md; the handle is the knob — the same definition as the switch's droplet: a round --paper droplet of --knob-size (= --slo-h × --knob-r, 0.78, Bencho's 36 in 46) with the same air all round, a 1px --border-strong stroke and a soft --ink shadow; the dots are --space-3 apart. Colours: well --track-bg, liquid --ink. No second slider exists — don't restyle input[type=range] in a tool.

Behaviour. Styled on the native input, no wrapper: value, step, keys, disabled and every tool's own input listener keep working, and code that does input.nextElementSibling.textContent = … (Colornet, Sinew, Living Path) still finds its number. Cursor is grab / grabbing on the slider and ew-resize on the number, which shows a light --border stroke on hover. Momentum (the value coasting after release) is off by default — it re-fires input every frame, which costs in tools that regenerate an image per input; opt in with data-momentum. Reduced-motion: rigid, no coast.

Checkbox & switch

One component, two shapes, drawn by us so they look identical in Chrome, Safari and Firefox. The real input[type=checkbox] is kept (state, label click, keyboard, disabled and every tool's JS are untouched) — only the drawing is replaced. Both shapes share one style definition and one set of springs, black and white with no hue: the switch is the Liquid toggle (after Bencho's, MIT) — a droplet that stretches along its travel and thins across it, draggable; the checkbox is the same object smaller — its tick springs in the same way.

Audit (Sep 29, 2026) — five implementations became one. Before: (1) 88 native checkboxes tinted with accent-color, drawn differently by every OS/browser; (2) FVS's own 26×14 switch; (3) header.css's 15px .org-check; (4) Camo Turing's hand-built 32×18 .toggle, a Strata port with a hardcoded white knob and 9px radius; (5) three bare checkboxes in Trellis that matched none of them. All 115 checkboxes in 16 tools now resolve to the same two shapes (14×14 / 28×14). Camo Turing's four toggles moved to .check-row.org-switch; the local .toggle CSS is deleted. The switch's spring lives in Organica.liquidSwitch() (core.js, applied by enhanceSliders) and writes --lx, --lsx, --lsy on the input — the real checkbox stays; a preset doing checkbox.checked = x still animates it. Which to use: a checkbox for an option in a list; a switch for a setting that takes effect the moment it flips. Put an info-tip inside a div.check-row, not a label (clicking the tip would toggle the switch).

Not this component — other on/off controls with their own entries: the floating toolbar's aria-pressed buttons, the layer card's dot toggle, the segmented control, and Sinew's .mini.on text buttons (still local to Sinew).

Thumbnail select picker

A dropdown whose rows carry a 26×26 pictogram — for choices a name alone doesn't convey (shape kinds, grid types). Built by Organica.selectPicker(selectEl, hostEl, { registry, ariaLabel }). The real <select> stays in the DOM (hidden) and stays the source of truth: picking a row sets select.value and dispatches a real change event, so every existing .value read/write and change listener keeps working. After changing the value or the options from code, call picker.refresh(). Options missing from the registry (added at runtime) still get a row, with a generic icon. Icons use currentColor so --ink comes from the component, never a hardcoded colour. The classes (.presets, .preset-trigger, .pt-ico, .pi-ico, .preset-menu, .preset-item) live in panel.css; Genesis, Camo Turing, Living Path, Sinew and Apostate use the same classes hand-wired.

Seeds panel

The tabbed Genesis / SVG / Text (optionally Image) source picker + Genesis thumbnail grid. Built by Organica.seedsPanel({ target, tabs, genesis, text, applyMode, onSeed, … }) — polymorphic on typeof target (element = generate the markup, string = attach to existing). onSeed(result) hands back both result.svgString (the canonical vector) and result.descriptor (raw {kind, formId, text, font, imageEl, …}) so each tool adapts whichever it needs. It is in flow, so it costs space. Going from 44px to 110px takes 66px off every canvas and panel. Nothing had to be re-measured: the shell is a flex column (#app{flex:1}) and the four pages that do height maths (Rhizome, Vortex, Membrane, Genesis) read --header-h. Verified on 11 pages: the workspace still ends exactly at the viewport, no scrollbar. Transparent means the header shows whatever is behind it — the page's white, or the hub's noise field — so never put a coloured background on body without checking the wordmark still reads.

Responsive. ≤820px: side padding --space-4, the "/ Page" suffix is dropped. ≤640px: the account name is hidden (avatar only). ≤600px: the circles shrink to 16px.

Per-tool palette contract

Every tool declares its own :root with the same seven names — that's the whole contract. Get the names right and every shared component (header, panel, floatbar, popover) inherits the tool's identity automatically; nothing shared ever hardcodes a hex.

:root {
  --ink: #0a0a0a;      /* text, thumbs, primary fills */
  --paper: #ffffff;    /* page & sidebar shell */
  --panel: #eceae4;    /* control fields, chips */
  --mid: #696256;      /* ≥4.5:1 on paper — sub-labels, values */
  --border: #d0c8b8;   /* decorative fills */
  --border-strong: #958462; /* ≥3:1 — rules the eye must register */
  --tool: #726a5e;     /* identity colour — focus ring, header accent */
}

--accent-warm and --track-bg are the two exceptions on purpose (see Color tokens) — every other visual difference between tools should come from these seven values, not from a component-level override.

Adding a token or class

Before adding anything, check whether it already exists — most "new" needs turn out to be an existing token at a slightly different pixel value, which is drift, not a gap.

A new spacing or radius value

Only add a step if you'll reuse it — a single one-off doesn't earn a token, it stays as a local rule in the tool's own <style>. If you do add one: it goes in tokens.css, in the existing scale, keeping the numbering contiguous (a new smallest spacing step becomes --space-0, not --space-9 tacked onto the wrong end).

A new component class

Decide which file owns it first (see File architecture): does it live in the header, the panel, the floatbar, or is it genuinely new? Name it .org-* if it's shared chrome, matching the existing .org-btn / .org-popover family. Add a live example to this page in the matching sidebar group — an element only counts as "in the system" once someone besides its author can find it here.

A new per-tool colour need

If it's a UI-chrome colour (another border weight, another text tone), it's almost certainly a variant of --mid/--border-strong, with contrast checked against both --paper and --panel — don't eyeball it, compute the ratio (see Color tokens for how --border-strong was derived). If it's the tool's own content colour (Halide's ink/paper for the dithered image, Pollen's point colour) it is not a design-system token at all — it's user data that happens to default near --ink/--paper. Don't tokenise it; see the first row of Common mistakes.

Common mistakes

Real ones, found auditing this codebase — not hypotheticals.

Retyping the stage shadow

Seven tools carried their own box-shadow: 0 4px 40px rgba(0,0,0,.18) on their sheet — two at .12, three more overriding the shared one to be lighter. They looked "almost" the same and drifted. Put class="org-stage" on the sheet, or box-shadow: var(--stage-shadow) where the class can't go. The id (#board, #preview…) is for the script, never for the style.

A grey canvas area

The area around the sheet used to be --panel, and six tools with their own stage area had copied that grey. Since Sep 29, 2026 it is var(--canvas-grid), var(--canvas-bg) everywhere; --panel is interface chrome only.

A font set outside --font

Switching the typeface showed six places that ignored it: a Georgia info tip, monospace readouts, a retired --mono, redirect stubs in sans-serif, and glyph-editor labels drawn on a canvas with system-ui. Every interface text uses var(--font); canvas text reads --font at draw time.

Treating user data as a design token

Spore/Pollen/Halide's ink & paper colour-swatch buttons have style="background:#0a0a0a" — that hex matches --ink by coincidence (it's the default artwork colour), not by role. It's set from the colour picker at runtime; forcing it to var(--ink) would be wrong the moment a user picks a different colour. Before "fixing" a hardcoded colour, check whether JS ever reassigns it.

A utility class that loses the cascade

.u-flex1 (one class, specificity 0-1-0) silently lost to .row .val (two classes, 0-2-0) already setting flex-shrink:0 — the browser doesn't care which file loaded last, only which selector is more specific. Found by checking getComputedStyle().flexGrow, not by reading the CSS. Every utility in this file now carries !important for exactly this reason.

Forcing a pill onto the corner-radius scale

Strata's toggle switch (border-radius: 9px on an 18px-tall track) and .method-pill (border-radius: 20px) are stadium shapes — radius = exactly half the element's height. Snapping either to --radius-md (4px) would leave visible flat corners, breaking the capsule. A radius on the token scale corners a rectangle; a radius that happens to equal half the height rounds it fully — they're different intents that look similar in the source.

A duplicate selector, silently overridden

Strata declared #shape-style-row twice in the same <style> block, 100 lines apart, with a different margin-top each time. CSS doesn't warn on this — the second declaration wins outright, and the first becomes dead code that looks live to anyone reading it top-to-bottom. grep -c the selector before trusting what a rule says it does.

Toggled visibility as a class, not an inline style

.u-hidden { display: none } looks like the obvious replacement for every style="display:none" in the codebase — except most of them are toggled from JS via el.style.display = show ? '' : 'none'. Clearing an inline style falls back to the stylesheet; if the stylesheet still has .u-hidden on the element, it stays hidden forever. Only apply the class to elements that are hidden once and never shown again (a permanently-hidden file-input trigger, for example).

The hidden attribute, beaten by a class's own display

Living Path's chain-toggle button had the hidden attribute and the .org-btn class. .org-btn sets its own display: inline-flex — an author rule, which always outranks the UA stylesheet's [hidden] { display: none }, regardless of source order. The button showed permanently despite hidden being set and cleared correctly by JS. Moving it to a class that never declares display (.mini, here) let the browser default win again. Before relying on hidden, check whether the element's own class sets display at all — if it does, either add an explicit .your-class[hidden]{display:none} rule or don't use hidden on it.

A capture-phase listener catching a descendant's own event

Living Path closed its (position:fixed) preset menu whenever .panel.right fired a scroll event, registered with useCapture:true so it would still catch the panel scrolling out from under the menu. But a capture-phase listener on an ancestor fires for any descendant's own matching event too — including the menu's own internal list scrolling once it had enough presets to overflow (Raster's 24; Vector's 5 never did, which is why this went unnoticed). The fix isn't removing capture, it's checking e.target inside the handler and ignoring events that originated inside the element you don't want to react to. Found by actually scrolling the menu, not by reading the listener — it looked correct on the page.

Self-check

This page is the reference, so it has to be able to fail. Three checks run on load; a red banner appears at the top only when one fails (a pass is silent, recorded as data-self-check="passed" on <body>) — a stale claim here shows up the moment someone opens the page, instead of at the next audit a year later.
